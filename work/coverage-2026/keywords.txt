k0 IPv4 주소 → MAC 주소 → ARP · 이름 → IP는 DNS
예시: 같은 IPv4 LAN에 있는 장비로 프레임을 보내려 한다. 목적지 IP 주소는 알고 있지만 MAC 주소를 모를 때 사용하는 프로토콜은?
답: ARP · IP 주소에 대응하는 링크 계층 주소를 알아내므로 ARP다. · 이름을 주소로 찾으면 DNS, 구형 MAC→자기 IP 결정은 RARP다.

k1 MAC → IP, 구형 주소 결정 → RARP · 실제 IP 자동 임대는 DHCP
예시: 주소를 저장하지 않은 단말이 자신의 MAC 주소를 서버에 보내 자기 IP 주소를 알아내던 구형 역주소 결정 프로토콜은?
답: RARP · MAC→자기 IP라는 역주소 결정과 구형 프로토콜이라는 조건이 RARP를 가리킨다. · 일반적인 IP·마스크·DNS 자동 임대는 DHCP다. MAC이라는 단어만으로 RARP를 고르지 않는다.

k2 IP·마스크·게이트웨이·DNS 자동 임대 → DHCP · 주소 변환은 NAT
예시: 신규 PC가 네트워크에 접속하면 서버에서 IP 주소, 서브넷 마스크, 기본 게이트웨이와 DNS 정보를 일정 기간 임대받는다. 해당 서비스는?
답: DHCP · 주소와 네트워크 설정을 자동으로 임대하는 서비스는 DHCP다. · NAT는 이미 쓰는 주소를 변환하며 설정 정보를 임대하지 않는다.

k3 사설 주소 ↔ 공인 주소 변환 → NAT · 포트도 구분해 다수가 공유하면 PAT/NAPT
예시: 회사 내부에서는 사설 IPv4 주소를 쓰고, 인터넷 통신 시 경계 장비에서 공인 주소로 변환한다. 이 주소 변환 기술은?
답: NAT · 사설 주소와 공인 주소 사이의 변환이 핵심이므로 NAT다. · 포트 번호도 함께 구분하여 여러 단말이 공인 주소를 공유한다고 명시하면 PAT/NAPT를 더 구체적으로 묻는 문제일 수 있다.

k4 장비 상태·트래픽·원격 관리·MIB → SNMP · 암호화 원격 로그인은 SSH
예시: 관리 서버가 Agent와 MIB를 이용해 여러 네트워크 장비의 상태와 트래픽 통계를 수집한다. 사용되는 관리 프로토콜은?
답: SNMP · 장비 관리 정보와 MIB·Agent라는 조합은 SNMP의 대표 단서다. · SSH는 암호화 원격 로그인이다. 원격 관리라는 표현만 읽지 말고 MIB를 확인한다.

k5 오류 통지·도달 불가·Echo → ICMP · 데이터 신뢰성 보장 기능 X
예시: IP 패킷 전달 과정에서 목적지 도달 불가나 시간 초과 같은 오류를 통지하고 Echo 요청·응답에도 사용하는 프로토콜은?
답: ICMP · IP 오류 통지와 Echo 메시지를 담당하는 것은 ICMP다. · ICMP는 오류 통지이며 TCP처럼 데이터를 재전송해 신뢰성을 보장하는 프로토콜이 아니다.

k6 IPv4 멀티캐스트 그룹 가입·탈퇴 → IGMP · IPv6에서는 MLD
예시: IPv4 멀티캐스트 방송에서 클라이언트가 그룹 가입·탈퇴 의사를 인접 라우터에 알린다. 이때 사용하는 프로토콜은?
답: IGMP · IPv4 멀티캐스트 그룹 멤버십 관리는 IGMP다. · 라우팅 경로를 계산하는 OSPF와 다르다. IPv6 그룹 관리 문맥이면 MLD를 구별한다.

k7 이름 → IPv4 → DNS A · IPv6이면 AAAA
예시: DNS 서버에 host.example.com의 IPv4 주소 192.0.2.10을 등록하려 한다. 적절한 레코드 형식은?
답: A · 호스트 이름을 IPv4 주소와 연결하는 레코드는 A다. · AAAA는 IPv6, PTR은 역방향, CNAME은 이름에 대한 별칭이다.

k8 IP → 이름·역방향 조회 → DNS PTR · IPv4 역방향 영역은 in-addr.arpa
예시: DNS에서 192.0.2.10이라는 IP 주소에 대응하는 호스트 이름을 역방향 조회하려 한다. 필요한 레코드 형식은?
답: PTR · IP→이름 방향의 역방향 조회이므로 PTR이다. · 이름→IPv4인 A와 방향을 바꿔 읽지 않는다.

k9 별칭을 실제 도메인 이름에 연결 → DNS CNAME · IP를 직접 지정하는 A와 구별
예시: www.example.com을 실제 호스트 이름 web01.example.com의 별칭으로 사용하려 한다. DNS에 추가할 레코드는?
답: CNAME · 이름을 다른 이름에 연결하는 별칭 레코드는 CNAME이다. · IP 주소를 직접 입력하는 A·AAAA 레코드와 구별한다.

k10 도메인의 메일 교환 서버 → DNS MX · 메일 전송 프로토콜은 SMTP
예시: example.com 도메인으로 수신되는 메일을 처리할 서버를 DNS에 지정하려 한다. 사용할 레코드는?
답: MX · 메일을 처리할 서버를 지정하는 DNS 레코드라는 조건에서 MX를 고른다. · SMTP는 메일 전달 프로토콜이다. 서버 지정 레코드를 묻는지 통신 프로토콜을 묻는지 확인한다.

k11 영역의 권한 정보·일련번호·갱신 주기 → DNS SOA · 이름 서버 지정은 NS
예시: DNS 영역의 일련번호와 보조 서버의 Refresh, Retry, Expire 정보를 저장하는 레코드는?
답: SOA · 영역 버전과 보조 서버의 갱신 정보를 담는 레코드는 SOA다. · NS는 영역의 이름 서버를 지정한다. 권한이라는 단어 하나만으로 NS와 혼동하지 않는다.

k12 캐시 유효 시간 → DNS TTL · 라우터 홉 제한과 구별
예시: DNS 레코드를 조회한 클라이언트나 재귀 서버가 그 결과를 캐시에 보관할 수 있는 유효 시간을 나타내는 값은?
답: DNS TTL · DNS 캐시의 유효 시간을 물으므로 DNS TTL이다. · IPv4 TTL·IPv6 Hop Limit은 패킷의 홉 제한을 나타낸다.

k13 메일 송신·서버 간 전달 → SMTP · 수신·메일함 접근은 POP3/IMAP
예시: 발신 메일 서버가 다른 도메인의 수신 메일 서버로 전자우편을 전달한다. 전통적으로 TCP 25번 포트를 사용하는 프로토콜은?
답: SMTP · 메일 서버 간 송신·전달과 25번 포트의 조합은 SMTP다. · POP3·IMAP은 사용자가 메일함에 접근하는 용도와 연결한다.

k14 서버의 메일함·폴더 동기화 → IMAP · POP3도 설정에 따라 서버 보관 가능
예시: PC와 스마트폰에서 같은 메일함의 폴더와 읽음 상태를 서버를 기준으로 동기화하려 한다. 적합한 메일 접근 프로토콜은?
답: IMAP · 서버 메일함과 폴더·상태를 여러 기기에서 함께 다루는 특징은 IMAP이다. · POP3를 사용하면 서버에 메일을 절대 남길 수 없다는 설명도 틀리므로 단정하지 않는다.

k15 제어 연결과 데이터 연결 분리 → FTP · TFTP는 UDP, SFTP는 SSH 기반
예시: 파일 전송에 사용자 인증과 명령을 위한 제어 연결, 파일 데이터를 위한 데이터 연결을 별도로 사용하는 프로토콜은?
답: FTP · 제어·데이터 연결을 분리하는 것이 FTP의 핵심 단서다. · TFTP는 UDP 기반이며 FTP와 같은 제어 연결 구조가 아니다.

k16 HTTP 데이터를 TLS로 보호 → HTTPS · 기본 포트 443
예시: 웹 서비스가 TLS를 사용하여 HTTP 데이터를 암호화하고 기본 포트 443을 사용한다. 이 프로토콜은?
답: HTTPS · HTTP 통신을 TLS로 보호하므로 HTTPS다. · 암호화라는 단어만 보면 SSH·IPsec도 후보가 될 수 있으므로 HTTP를 확인한다.

k17 신호 재생·전송 거리 연장 → 리피터, L1 · MAC 학습 X
예시: 먼 거리를 지나며 약해진 디지털 신호를 재생하여 전달한다. MAC이나 IP에 따른 경로 선택은 하지 않는 이 장비와 OSI 계층의 연결은?
답: 리피터–1계층 · 신호를 재생하는 리피터는 물리 계층 장비다. · MAC 학습과 프레임 전달을 수행하는 브리지는 데이터링크 계층이다.

k18 목적지 MAC으로 프레임 전달 → L2 스위치·브리지 · 목적지 IP 기반이면 L3
예시: 출발지 MAC 주소를 학습해 테이블을 만들고 목적지 MAC 주소를 기준으로 프레임을 전달하는 장비는?
답: L2 스위치 · MAC 테이블을 학습하고 프레임을 전달하는 대표 장비는 L2 스위치다. · IP 주소로 네트워크 사이의 경로를 선택하는 장비는 라우터·L3 스위치다.

k19 서로 다른 IP 네트워크 사이 경로 선택 → 라우터·L3 스위치 · 단순 L2 전달과 구별
예시: 목적지 IP 주소와 라우팅 테이블을 이용하여 서로 다른 IP 네트워크 사이로 패킷을 전달하는 장비는?
답: 라우터 · IP 경로를 선택하는 네트워크 계층 장비는 라우터다. L3 스위치도 같은 계층의 전달을 수행한다. · MAC 기반의 단순 L2 전달과 구별한다.

k20 논리적으로 브로드캐스트 도메인 분리 → VLAN · 루프 방지는 STP
예시: 하나의 물리적 스위치에 연결된 영업부와 개발부 단말을 서로 다른 논리적 브로드캐스트 도메인으로 분리하려 한다. 사용할 기술은?
답: VLAN · 물리 연결과 무관하게 논리적인 L2 그룹으로 나누는 것은 VLAN이다. · 루프 방지는 STP, VLAN 정보 전파는 VTP, 링크를 묶는 것은 LACP다.

k21 이중화된 L2 경로의 루프 방지 → STP · VLAN 정보 동기화는 VTP
예시: 스위치를 이중 경로로 연결한 뒤 루프로 인한 브로드캐스트 폭주가 발생했다. 일부 경로를 차단하여 루프를 방지하는 프로토콜은?
답: STP · L2 루프를 막기 위해 논리적으로 일부 경로를 차단하는 것은 STP다. · VLAN 설정 동기화나 링크 대역폭 확대를 묻는 문제와 다르다.

k22 스위치 사이 VLAN 프레임 태그 → IEEE 802.1Q · VTP가 태깅 규격인 것은 아님
예시: 스위치 간 한 링크에 여러 VLAN의 트래픽을 전달하기 위해 이더넷 프레임에 VLAN 식별 태그를 넣는다. 해당 표준은?
답: IEEE 802.1Q · 이더넷 VLAN 태깅 표준은 IEEE 802.1Q다. · 802.1X는 포트 기반 네트워크 접근 인증이다.

k23 여러 스위치의 VLAN 정보 동기화 → VTP · Cisco 기술, 버전 조건 확인
예시: Cisco 스위치 환경에서 한 스위치의 VLAN 설정 정보를 같은 관리 도메인의 다른 스위치에 전파·동기화한다. 해당 프로토콜은?
답: VTP · Cisco 환경의 VLAN 설정 정보 전파·동기화는 VTP다. · VLAN 프레임에 태그를 넣는 802.1Q와 역할을 구별한다.

k24 여러 링크를 하나로 묶기 → 링크 집성·LACP · VLAN 분리와 구별
예시: 스위치 사이의 물리 링크 여러 개를 하나의 논리 링크로 묶고, 구성 협상을 표준 프로토콜로 처리하려 한다. 해당 프로토콜은?
답: LACP · 링크 집성을 협상하는 대표적인 표준 프로토콜은 LACP다. · VLAN 분리나 루프 차단 자체를 묻는 내용이 아니다.

k25 IP·TCP/UDP 포트 기반 부하분산 → L4 스위치 · URL·쿠키는 L7 단서
예시: 로드밸런서가 IP 주소와 TCP/UDP 포트 번호를 기준으로 연결을 여러 서버에 분배한다. 대표적인 장비 분류는?
답: L4 스위치 · 전송 계층의 포트 정보를 기준으로 분배하므로 L4 스위치로 분류한다. · URL·쿠키 같은 응용 내용을 기준으로 하면 L7 단서다.

k26 URL·쿠키·응용 내용 기반 분산 → L7 스위치 · HTTPS 내용 판단에는 TLS 처리 조건 필요
예시: TLS 종료 후 HTTP 요청의 URL 경로와 쿠키를 읽어 요청을 서로 다른 서버 그룹에 분배한다. 해당 장비 분류는?
답: L7 스위치 · 응용 계층 내용을 해석해서 분배하므로 L7 스위치다. · 암호화된 HTTPS 내용을 그대로 읽는다는 뜻은 아니다. 예시에서는 TLS 종료 조건이 주어졌다.

k27 HTTP/HTTPS 웹 공격 방어 → WAF · 모든 종류의 공격 방어 X
예시: 웹 서버 앞에서 HTTP 요청을 검사하여 SQL 삽입과 XSS 같은 웹 응용 공격을 차단하는 보안 장비는?
답: WAF · 웹 프로토콜과 웹 응용 공격을 전문적으로 검사하는 장비는 WAF다. · 일반 방화벽의 모든 기능이나 모든 공격 방어를 보장하는 표현으로 확대하지 않는다.

k28 제어 평면·데이터 평면 분리·컨트롤러 → SDN · 기능 소프트웨어화는 NFV
예시: 네트워크 장비의 제어 평면과 데이터 평면을 분리하고 중앙 컨트롤러에서 전달 동작을 프로그래밍한다. 이 기술은?
답: SDN · 평면 분리와 프로그래밍 가능한 제어가 SDN의 결정 단서다. · 장비 기능을 범용 서버의 소프트웨어로 제공하는 것은 NFV다.

k29 방화벽·라우터를 범용 서버의 VNF로 제공 → NFV · 물리 서버가 필요 없어지는 것 X
예시: 전용 장비로 운영하던 방화벽과 로드밸런서 기능을 범용 서버의 VNF로 구현해 필요에 따라 배포·확장한다. 해당 기술은?
답: NFV · 네트워크 기능의 소프트웨어 가상화가 NFV다. · SDN의 핵심은 제어·데이터 평면 분리다. NFV도 실행할 물리 인프라는 필요하다.

k30 가상 머신·가상 스위치·하이퍼바이저 → Hyper-V · 컨테이너와 동일 개념 X
예시: Windows Server에서 하이퍼바이저를 사용하여 여러 가상 머신과 가상 스위치를 운영하려 한다. Microsoft의 해당 가상화 기능은?
답: Hyper-V · Microsoft의 하이퍼바이저 기반 가상화 기능은 Hyper-V다. · IIS는 웹 서비스, AD는 도메인 기반 계정·자원 관리와 연결한다.

k31 다수 안테나 송수신 → MIMO · 다중화·변조와 구별
예시: 무선 통신에서 여러 송신·수신 안테나를 사용하여 공간 스트림을 활용한다. 이 다중 안테나 기술은?
답: MIMO · 다수 안테나로 공간 자원을 활용하는 기술은 MIMO다. · WDM은 빛의 파장별 다중화이고 TDM은 시간 분할이다.

k32 NIC로 네트워크 부팅 → PXE · 원격 전원 켜기는 Wake-on-LAN
예시: 운영체제가 설치되지 않은 PC가 NIC를 통해 네트워크 서버의 부팅 이미지를 받아 시작한다. 이 네트워크 부팅 기술은?
답: PXE · 네트워크 인터페이스로 부팅 환경을 가져오는 것은 PXE다. · Wake-on-LAN은 원격 전원 켜기와 관련되며 부팅 이미지를 받는 기술 자체가 아니다.

k33 코어·클래딩·빛·전반사 → 광케이블 · UTP·동축은 구리 기반
예시: 중심부의 코어와 이를 감싸는 클래딩으로 구성되며, 빛의 전반사를 이용해 데이터를 전달하는 매체는?
답: 광케이블 · 코어·클래딩과 빛의 전반사는 광케이블을 가리킨다. · 구리 전류를 이용하는 UTP·동축과 구별한다.

k34 서로 다른 프로토콜 체계 변환 → 게이트웨이 · 기본 게이트웨이는 보통 다음 홉 라우터
예시: 서로 다른 통신 프로토콜 체계를 사용하는 시스템 사이에서 형식과 프로토콜을 변환해 통신을 가능하게 한다. 이 기능을 수행하는 장치는?
답: 게이트웨이 · 여기서는 프로토콜 변환을 수행하는 일반적인 게이트웨이를 묻는다. · IP 네트워크의 기본 게이트웨이는 보통 다음 홉 라우터를 뜻하므로 두 문맥을 구분한다.

k35 미러링 → RAID 1 · 동일 데이터 복제
예시: 동일 용량 디스크 두 개에 같은 데이터를 복제하여 한 디스크가 고장 나도 다른 디스크의 데이터를 사용하는 방식은?
답: RAID 1 · 두 디스크에 동일 내용을 복제하는 미러링은 RAID 1이다. · 분산 패리티가 아니라 데이터 자체를 복제한다. 성능의 최고·최저 같은 표현으로 판단하지 않는다.

k36 분산·회전 패리티 → RAID 5 · 최소 3개, 디스크 1개 장애 허용
예시: 최소 3개의 디스크에 데이터를 스트라이핑하고 패리티를 여러 디스크에 분산하여 디스크 1개 장애를 허용하는 방식은?
답: RAID 5 · 분산 패리티와 디스크 1개 장애 허용이 RAID 5의 단서다. · RAID 6은 이중 패리티로 디스크 2개 장애를 허용하는 전형적인 구성이다.

k37 패리티 없는 스트라이핑 → RAID 0 · 장애 복구용 중복성 없음
예시: 데이터를 여러 디스크에 나누어 기록하지만 패리티나 미러링을 제공하지 않아 한 디스크 장애로 데이터가 손실될 수 있다. 해당 RAID는?
답: RAID 0 · 중복성 없이 스트라이핑만 수행하는 방식은 RAID 0이다. · RAID라는 이름이 붙었다고 모든 레벨이 장애 복구용 중복성을 제공하는 것은 아니다.

k38 순차적으로 돌아가며 분배 → Round Robin · 가중치 조건이면 Weighted Round Robin
예시: 서버 A, B, C에 요청을 A→B→C→A 순서로 돌아가며 분배한다. 서버별 가중치는 동일하다. 해당 알고리즘은?
답: Round Robin · 동일 가중치로 순서대로 분배하는 것은 Round Robin이다. · 현재 연결 수가 가장 적은 서버를 선택하는 것과 다르다.

k39 연결 수가 가장 적은 서버 → Least Connections · 순번 기준 X
예시: 새 연결이 들어오면 현재 활성 연결 수를 비교해 가장 적은 연결을 처리 중인 서버에 배정한다. 해당 방식은?
답: Least Connections · 현재 연결 수가 최소인 서버를 선택하므로 Least Connections다. · 순번대로 돌아가는 Round Robin과 판별 기준이 다르다.

k40 중앙 장비·단말 추가 쉬움 → Star · 중앙 장비 장애와 단말 장애 구별
예시: 각 단말이 중앙 스위치에 개별 회선으로 연결되어 단말 추가가 쉽다. 중앙 장비 장애 시 전체 연결이 영향을 받는 토폴로지는?
답: Star · 중앙 장비를 중심으로 단말을 연결하는 구성은 Star다. · 단말 한 대의 고장과 중앙 장비의 고장을 구별한다.

k41 모든 노드를 상호 연결 → 완전 Mesh · 회선 수 n(n−1)/2
예시: 모든 노드 쌍을 전용 회선으로 직접 연결해 우회 경로를 확보한다. 노드 n개에 필요한 회선 수가 n(n−1)/2인 구성은?
답: 완전 Mesh · 모든 쌍을 연결하는 완전 Mesh의 무방향 회선 수는 조합 nC2다. · 일부 노드만 그물처럼 연결한 부분 Mesh와 구별한다.

k42 하나 보내고 ACK 대기 → Stop-and-Wait ARQ · 대기로 효율 저하
예시: 송신 측이 프레임 하나를 보낸 뒤 ACK를 받을 때까지 다음 프레임을 보내지 않는다. 해당 재전송 방식은?
답: Stop-and-Wait ARQ · 한 프레임씩 송신하고 응답을 기다리는 정지-대기 방식이다. · 여러 프레임을 연속 송신하는 방식과 구별한다.

k43 오류 프레임부터 이후까지 재전송 → Go-Back-N ARQ · 오류 프레임만 보내는 것 X
예시: 여러 프레임을 연속 전송하던 중 3번 프레임에 오류가 발생했다. 송신 측이 3번부터 그 이후 전송한 프레임까지 다시 보낸다. 해당 방식은?
답: Go-Back-N ARQ · 오류 프레임부터 이후 프레임까지 재전송하는 것이 Go-Back-N이다. · 오류 프레임만 다시 보내는 방식은 Selective Repeat다.

k44 오류 프레임만 재전송 → Selective Repeat ARQ · 수신 버퍼·재정렬 필요
예시: 연속 전송 중 3번 프레임만 손실되었다. 수신 측은 정상 프레임을 보관하고 송신 측은 3번 프레임만 다시 보낸다. 해당 방식은?
답: Selective Repeat ARQ · 정상 프레임은 보존하고 오류·손실 프레임만 선택해 재전송한다. · Go-Back-N처럼 오류 이후의 정상 프레임까지 모두 재전송하지 않는다.

k45 채널 상태에 맞춰 블록 길이 변경 → Adaptive ARQ · 제공 자료의 시험용 분류
예시: 채널의 오류 상태에 따라 데이터 블록의 길이를 동적으로 바꿔 전송 효율을 높이는 ARQ 방식은?
답: Adaptive ARQ · 제공 자료의 시험용 분류에서 채널 상태에 맞춰 블록 길이를 바꾸는 방식은 Adaptive ARQ다. · 오류 이후 몇 개를 재전송하는지가 아니라 블록 길이의 적응적 변경이 결정 단서다.

k46 고정 시간 슬롯·데이터 없어도 할당 → 동기식 TDM · 통계적 TDM과 구별
예시: 각 회선에 고정된 시간 슬롯을 주기적으로 할당한다. 어떤 회선에 보낼 데이터가 없어도 해당 슬롯을 다른 회선이 쓰지 못하는 방식은?
답: 동기식 TDM · 고정 슬롯을 유지하여 유휴 슬롯이 생길 수 있는 방식은 동기식 TDM이다. · 보낼 데이터에 따라 슬롯을 효율적으로 배분하는 통계적 TDM과 구별한다.

k47 빛의 파장별 다중화 → WDM · FDM은 주파수, TDM은 시간
예시: 하나의 광섬유에 서로 다른 파장의 광 신호를 동시에 실어 여러 채널을 전달한다. 이 다중화 방식은?
답: WDM · 빛의 파장별로 채널을 나누므로 WDM이다. · 시간 슬롯 분할은 TDM이다.

k48 토큰을 가진 노드만 전송 → 토큰 패싱 · 충돌 감지 방식 X
예시: 네트워크의 전송 권한을 나타내는 토큰이 순환하며 토큰을 가진 노드만 데이터를 전송한다. 이 매체 접근 방식은?
답: 토큰 패싱 · 전송 권한을 순환 토큰으로 부여하는 방식은 토큰 패싱이다. · 채널 감지와 충돌 감지·회피를 이용하는 경쟁 방식과 구별한다.

k49 무선·백오프·선택적 RTS/CTS → CSMA/CA · 구형 공유 이더넷은 CSMA/CD
예시: 무선 LAN 단말이 송신 전에 채널을 살피고 랜덤 백오프를 수행한다. 필요하면 RTS/CTS를 사용해 충돌을 회피한다. 해당 방식은?
답: CSMA/CA · 무선 환경에서 충돌을 회피하는 매체 접근 방식은 CSMA/CA다. · 구형 공유 이더넷의 CSMA/CD는 충돌 감지와 연결한다.

k50 명령을 커널에 전달 → Shell · 핵심 자원 관리는 Kernel
예시: Linux에서 사용자 명령을 해석하고 실행을 요청하여 사용자와 커널 사이의 인터페이스 역할을 수행하는 구성요소는?
답: Shell · 명령 해석과 사용자 인터페이스를 제공하는 것은 Shell이다. · CPU·메모리 등 핵심 자원 관리는 Kernel, 부팅 초기 운영체제 적재는 부트 로더다.

k51 부팅 자동 마운트 설정 → /etc/fstab · 현재 상태 조회와 구별
예시: Linux 부팅 시 자동으로 마운트할 파일시스템과 마운트 지점·옵션을 설정하는 대표적인 파일은?
답: /etc/fstab · 부팅 자동 마운트 항목과 옵션을 지정하는 설정 파일은 /etc/fstab이다. · 현재 마운트 상태를 조회하는 mount·findmnt 명령을 묻는 문제와 구별한다.

k52 내부 웹 리소스를 외부에 게시하는 Windows 역할 → Web Application Proxy · VPN 접속 자체와 구별
예시: Windows Server에서 원격 PC를 사내 네트워크에 VPN으로 연결하는 대신 내부 웹 응용을 인터넷에 게시하는 역할 서비스는?
답: Web Application Proxy · 내부 웹 응용을 외부에 게시하는 역할 서비스는 Web Application Proxy다. · VPN이나 DirectAccess처럼 원격 PC를 사내 네트워크에 연결하는 것과 목적이 다르다.

k53 도메인 안 부서별 관리 단위 → OU · 도메인 자체를 새로 만드는 것 X
예시: 하나의 Active Directory 도메인 안에서 영업부·개발부 등의 관리 단위를 만들고 관리 권한 위임과 그룹 정책 적용에 활용하려 한다. 구성할 단위는?
답: OU · 한 도메인 내부의 조직 구성 단위는 OU다. · 새 도메인·포리스트를 만드는 것과 다르다.
