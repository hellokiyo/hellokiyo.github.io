1 문서 목적 및 결론
본 문서는 실제 코딩·설치 이전에 기술 선택의 근거, 서버 및 프로젝트 구조, 내부망 의존성 공급, 형상관리, 배포·검증 방식을 합의하기 위한 설계 초안이다. 권장안은 Vue 3 프론트엔드와 eGovFrame 5.0 기반 Spring Boot 3.5 계열 REST 백엔드를 개발 시 분리하고, 운영에서는 Vue 정적 산출물을 Spring Boot 실행형 JAR에 포함해 단일 포트로 서비스하는 방식이다. 별도 WEB 서버는 보안·운영 기준이 요구하는 경우 추가한다.

3 시스템 논리 아키텍처
브라우저 → Vue 3(라우터·Pinia·SCSS·기존 jQuery 플러그인) → /api REST/JSON → Spring MVC Controller → Service/트랜잭션 → MyBatis Mapper(XML) → Oracle. 운영 시 같은 Spring Boot 서버에서 /assets 등 정적 파일을 제공하며 /api만 백엔드 API로 처리한다.
개발 모드: Vite 개발 서버와 Spring Boot API 서버를 별도 실행하고 Vite proxy로 /api 연결. CORS 의존을 최소화한다.
운영 모드: npm 빌드의 dist 산출물만 JAR의 static 리소스로 포함. Node.js 개발 도구는 운영 서버 필수 아님.
인증·세션: 사내 SSO 여부부터 확인. 쿠키 세션 또는 토큰 방식은 보안 정책에 따라 결정; CSRF/CORS/쿠키 속성까지 함께 설계.
WEB 서버: 최초에는 내장 Tomcat + JAR을 선택. TLS 종료, DMZ, WAF, 접속 통제, 공통 리버스 프록시 정책이 있으면 기존 WEB 서버 앞단 배치.

5 버전 호환성 및 의존성 원칙
eGovFrame 5.0 실행환경은 Spring Framework 6.2.11, Java 17 이상, Spring Boot 구성 시 Servlet 6.0 이상을 기준으로 공식 안내한다.
Spring Boot 3.5.x와 MyBatis Spring Boot Starter 3.0 계열을 우선 검토한다. MyBatis 공식 표에서는 Starter 3.0이 Boot 3.2~3.5를 지원한다.
eGovFrame Boot 부모 BOM과 Spring Boot BOM의 중복 관리·버전 충돌을 dependency:tree로 확인한다. eGov 데이터접근 모듈과 MyBatis 자동구성을 중복 적용하지 않도록 구성 방식을 선택한다.
Oracle JDBC 드라이버는 DB 서버 버전·JDK 17 지원·사내 라이선스·Nexus 반입 가능 여부를 DBA와 확인 후 고정한다.
Java·Node·npm·Vite·Vue·Pinia·jQuery·Sass·Maven 버전은 검증 완료 시 lock/bom 및 버전표로 동결한다.
6 프로젝트 디렉터리 및 SVN 구조
SVN 저장소: /trunk, /branches, /tags. /trunk 아래 backend/, frontend/, docs/, deploy/를 두고, 프로젝트 전체를 한 번에 체크아웃한다. 운영 산출물과 비밀값은 SVN에 커밋하지 않는다.
backend/src/main/java/{기관패키지}/common, feature/{업무}/controller, service, mapper, dto; backend/src/main/resources/application.yml, application-dev.yml, application-prod.yml, mapper/oracle/*.xml; backend/src/test; frontend/src/components, views, router, stores, api, styles, legacy; frontend/public; docs/architecture, environment, deployment, test; deploy/scripts, templates.
프론트엔드: Vue가 DOM을 소유하는 영역에서는 jQuery로 동일 요소를 직접 변경하지 않는다. 레거시 플러그인은 Vue 컴포넌트 mount/unmount 시 초기화·해제를 래핑한다.
기존 퍼블리싱 이관: 화면별 HTML→Vue SFC, CSS→SCSS, JS→컴포넌트 로직으로 구분. 외부 CDN·폰트·이미지 링크는 내부 자산으로 전환한다.
SVN ignore: target/, node_modules/, dist/, .env.local, 로그, IDE 개인 설정, 인증서·비밀번호. .vscode/extensions.json 및 검증된 공용 설정은 버전 관리한다.

8 데이터·API·보안 설계
계층: Controller는 요청 검증·응답, Service는 업무 규칙·트랜잭션, Mapper는 SQL을 담당한다. Oracle SQL과 Java 객체 필드 매핑 규칙을 명시한다.
DB: 전용 최소 권한 계정, JDBC 연결 풀, 쿼리 타임아웃, 커밋·롤백, 날짜·타임존, 페이징, 시퀀스/키 생성 방식을 협의한다.
API: /api/v1 경로, JSON UTF-8, 공통 오류 응답, 입력 검증, 예외 처리, 접근 로그에서 개인정보 마스킹을 정의한다.
보안: 인증 연동, 인가, CSRF, XSS, SQL 파라미터 바인딩, 파일 업로드, 비밀번호/비밀키 보관, TLS, 감사 로그 정책을 승인받는다.
9 빌드 및 Windows 운영 배포
빌드 흐름: SVN trunk/tag 체크아웃 → npm ci → Vue 빌드 → dist 산출물 검증 → 백엔드 static 포함 → Maven verify/package → 실행형 JAR 생성 → 승인된 서버로 반입 → 구성파일 주입 → 서비스 등록 및 기동 → 헬스·기능 점검. CI가 없다면 동일 순서의 표준 수동 배포 절차를 운영한다.
설정: application.yml에는 공통값, application-dev/prod.yml에는 환경별 비밀 아닌 설정을 두고 DB 비밀번호 등은 환경변수·외부 보안 저장소로 주입한다.
Windows 운영: 전용 서비스 계정과 권한, 서비스 래퍼/사내 승인 도구, 자동 재시작, 로그 경로, 백업 및 롤백(이전 JAR+설정)을 정의한다.
기동 확인: 지정 포트 리슨, /actuator/health 공개 범위 통제, Oracle 연결·API 응답·Vue 새로고침 라우팅 확인.
네트워크: 방화벽 인바운드 최소 개방, Oracle은 WAS→DB만 허용. HTTPS 인증서와 프록시 헤더 적용 여부는 보안부서 정책에 따른다.
