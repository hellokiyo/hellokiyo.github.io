# 사용자 설정과 개발 설정

확인 기준: 2026-11-15. 화면의 사용자 설정과 개발자 파일 설정을 구별한다. 설정 화면은 시험 일정 → 화면 테마 → 앱 설치와 업데이트 → 학습 기록 관리로 구분했다.

## 사용자가 바꾸는 설정

| 항목 | 적용 시점·기본값 | 저장/백업 | 담당 파일 |
|---|---|---|---|
| 시험일 | 시험일 저장 버튼. 기존 날짜가 없으면 `ReviewCore.DEFAULT_EXAM` 사용(현재 2026-11-14) | 학습 JSON에 포함. 복습 일정을 재계산 | `platform/settings-controller.js`, `domain/review-core.js` |
| 화면 테마 | 화이트 기본. 시스템/화이트/블랙/웜 베이지/소프트 그린, 선택 즉시 적용 | 별도 테마 키. 학습 JSON 미포함. 시스템 모드만 OS 색 변경 추종 | `platform/themes.js`, `css/themes.css` |
| 홈 화면 설치 | 브라우저가 지원할 때 설치 버튼. iPhone 등은 브라우저 메뉴 안내 | 앱 설치는 학습 JSON과 별개 | `platform/pwa.js`, 루트 manifest |
| 최신 파일 갱신 | 설정의 업데이트 UI에서 수행. 개인 기록과 캐시 구분 | 캐시 정리가 학습 기록 초기화가 아님 | `platform/pwa.js`, `sw.js` |
| 기록 내보내기 | 학습 상태와 게임 진행을 JSON 파일로 다운로드 | 개인 원본 파일·테마·추천 사용 시간은 제외 | `platform/settings-controller.js` |
| 기록 가져오기 | 2MB 이하, 앱/버전 확인 후 정제. 덮어쓰기 확인 뒤 반영 | 알 수 없는 ID·잘못된 답안 등을 정제. 구버전 게임 필드 부재는 기존 게임 기록 유지 | 위 파일, `domain/core.js`, 게임 모듈 |
| 학습 기록 초기화 | 확인 다이얼로그 승인 후 학습 상태 초기화 | 학습 상태와 추천 이용 기록 초기화. 테마·개인 자료·게임 기록은 유지 | 위 파일, `app.js`의 onReset |

시험일 기본값은 운영자가 최신 시험 일정에 맞춰 관리해야 한다. 일정 자동 조회 기능은 없다. 화면별 분류/검색, 학습 시간, 게임 모드 등은 각 화면에서 선택하는 값이며 설정 대화상자와 별개다.

## 저장소 계약

| 저장소/키 | 데이터 | JSON 내보내기에 포함 |
|---|---|---|
| localStorage `network-notes:v1` | 암기·읽음·계획·일일 목표·문제 답안/세션·최근 결과·복습 일정·기능별 오답 | 예 |
| localStorage `network-notes:v1:before-adaptive` | 초기 적응형 전환 전 보존본 | 아니오 |
| localStorage `network-keyword-rain:v1` | 모드별 최고점·GP·게임 진행 | `gameProgress`로 포함 |
| localStorage `network-notes:theme` | 테마 선호 | 아니오 |
| localStorage `network-study-coach:v1` | 최근 7일 활성 시간·당일 숨김 | 아니오 |
| IndexedDB `network-notes-materials:v1` / `materials` | 개인 원본 Blob·제목·분류·메모·검토 표시 | 아니오. 별도 자료 ZIP 사용 |
| Cache Storage `network-notes-pwa-v23` | 앱 자산·오프라인 응답 | 아니오. 개인 학습 상태를 대신하는 백업이 아님 |

저장 키와 문제 ID는 이번 폴더 재배치에서 바꾸지 않았다. file/localhost/공개 HTTPS와 포트가 다르면 저장소도 달라질 수 있다. 서버 계정이 없으므로 다른 기기의 기록이 자동으로 나타나지 않는다. 중요한 기록은 원래 주소에서 내보내고 새 주소에서 가져온다.

## 개발·호스팅 설정 파일

| 파일 | 이유·수정 시 주의 |
|---|---|
| `index.html` | 데이터 → 도메인 → 화면/UI → app 조립 순서를 명시. 테마 스크립트는 초기 색 적용을 위해 먼저 실행 |
| `manifest.webmanifest` | 앱 이름·아이콘·시작 경로·범위. 루트/하위 경로 호스팅을 고려해 상대 주소 사용 |
| `sw.js` | 서비스 워커는 루트 앱 범위를 유지. 새/이동 자산은 목록과 버전을 함께 수정 |
| `.nojekyll` | 정적 파일을 그대로 제공하는 현재 호스팅 진입점 |
| `_config.yml` | 현재 .nojekyll 환경에서는 사용하지 않는 Jekyll 복귀용 메타데이터. 이 파일의 exclude가 공개 업로드 파일을 숨겨 준다고 가정하지 않음 |
| `.prettierrc.json`, `.prettierignore` | 서식 규칙과 생성 데이터 제외. 실행에는 포매터 불필요 |
| `AGENTS.md` | Git 금지·설계 책임·검증·질문/승인 기록 규칙 |
| `.agents/skills/` | 재사용 개발 성장 기록 지침. 앱 실행 코드가 아님 |

`.idea`, `.git` 등 기존 관리 폴더는 삭제하거나 설정을 변경하지 않았다. `work`에는 작업용 스크립트/도구가 있고 `audits`는 당시 검증 증거다. 정적 호스팅은 올린 파일을 공개할 수 있으므로 운영자가 필요한 배포 파일을 선택해야 한다. 이 작업에서 배포는 수행하지 않는다.

## 재현 연습

1. JSON 내보내기 전 오답 수와 시험일을 확인한다.
2. 별도 테스트 주소에서 가져오고 값이 유지되는지 확인한다.
3. 테마와 개인 자료 파일은 JSON에서 이동하지 않는다는 점을 확인한다.

원래 주소에서 사이트 데이터를 지우는 것으로 실습하지 않는다. 자세한 복구는 [운영 절차](operations.md)를 따른다.

설정 상단의 ‘1분 사용법’은 설정 창을 닫고 #help로 이동한다. 새 계정·AI 키 설정은 추가하지 않았다.
