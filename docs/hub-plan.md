# 메인 허브와 독립 서비스 분리 제안

상태: 2026-11-14 설계 제안. 현재 루트 시험 사이트를 이동하거나 공개 사이트를 변경한 것은 아니다.

## 목적

메인은 각 서비스의 목적과 진입점을 보여주는 정적 허브로 두고, 시험 공부 화면은 독립 경로에 유지한다. 사용자는 기능을 찾기 쉬워지고 유지보수자는 어느 프로젝트를 고칠지 구별하기 쉬워진다. 로그인·DB·유료 API·접속 비밀 값은 허브에 도입하지 않는다.

제안 경로(현재 존재/배포를 뜻하지 않음):

```text
/                 서비스 허브
/network/         합격루틴 시험 학습
/linux/           Linux 학습 자료
/projects/        공개 가능한 프로젝트 소개/링크
```

실제 다른 프로젝트의 공개 범위와 준비 상태는 확인 후 정한다. 소스에 other-projects/linux-study-hub가 존재한다고 운영/검수 완료로 간주하지 않는다. 개발 일지·승인 로그·개인 홈랩 관리 화면을 자동으로 공개 메뉴에 노출하지 않는다.

## 로컬 AI와의 관계

허브의 링크는 탐색 진입점이다. 집 안 AI로의 네트워크 연결, 방화벽 허용, 인증, API 통합이나 모델 간 협업을 만들어 주지 않는다. 공개 정적 사이트와 사설 AI는 경계를 유지한다. AI 카드가 필요하면 집 안 전용이라는 안내와 사용자가 선택하는 이동 흐름을 제공한다. 공개 소스에는 연결 코드·쿠키·대화 ID·개인 서버의 관리 접속 정보를 넣지 않는다. 로컬 서버를 자동 탐색하거나 CORS/브라우저 보호를 해제하지 않는다.

문제별 질문은 당장 문제/보기/내 답 복사와 기존 AI 별도 사용을 우선 검토한다. 직접 연동은 동일 로컬 출처의 시험 화면과 기존 AI API 계약을 검증한 후 별도로 진행한다.

## AI 도구가 이해하기 쉬운 구조

공개 허브에는 서비스 이름·목적·링크를 일관된 형태로 둔다. 유지보수용 문서에는 프로젝트별 실행 방법·담당 모듈·확인된 API 계약·검증 상태를 정리한다. URL이 있다고 AI에게 접근 권한이 생기지는 않는다. 도구/네트워크가 허용한 자료에만 접근할 수 있다. 계정·토큰 없이 가능한 범위와 현재 미연결 상태를 문서에 명시한다.

## 이동 전 확인할 것

- 예전 /#quiz 등 북마크에서 시험 화면으로 이어지는 경로를 보존한다.
- 동일 origin의 localStorage 키/ID를 유지하고 도메인·프로토콜·포트가 바뀌는 경우 백업 차이를 안내한다. 경로만 옮겼다고 기록을 삭제하지 않는다.
- 서비스 워커의 기존 루트 범위와 새 서비스 범위를 점검해 허브/다른 앱 캐시가 간섭하지 않게 한다. 기존 설치 PWA 업데이트를 별도 검증한다.
- manifest 시작 URL, 가이드 다운로드, 자료·그림·CSS·생성 스크립트의 상대 경로를 함께 검증한다.
- 기존 학습 기능·오답·진도·뒤로가기·모바일 내비게이션 회귀 검사 뒤 전환한다.

현 단계는 구조 제안과 파일 존재 확인만 수행했다. UI 구현, 기존 경로 변경, 실제 사용자 시험, 공개 호스트 점검, Git/배포는 수행하지 않았다.

## 후속 방향 확인

합격루틴은 다른 프로젝트와 섞지 않는 시험 전용 서비스로 유지하는 방향이다. 허브 전환이나 /network/ 이동은 현재 실행 계획으로 확정하지 않았다. AI는 무료 개인 로컬 도구를 활용하는 선택적 학습 보조이며 공개 앱의 필수 실행 의존성이 아니다. 직접 연결은 아직 구현하지 않았다.
