# 합격루틴 운영과 변경 검증

## 운영 기준

정적 개인 학습 서비스로 사용할 수 있는 변경·검증·복구 절차를 정의한다. 중앙 서버 모니터링, 계정 복구, 자동 고객지원, 실제 기기 전수 검증이 완료된 상용 서비스라는 의미는 아니다. Git 연결·업로드·게시 여부는 사용자가 관리한다.

## 변경 전후 순서

1. 현재 사용 브라우저의 설정에서 학습 기록 JSON을 내보낸다. 파일 자료는 별도로 원본을 보관한다.
2. 변경할 기능과 정상/실패/새로고침 시 기대 동작을 개발 일지에 남긴다.
3. 데이터 ID를 유지하고 담당 모듈을 수정한다. 새 자산은 index와 서비스 워커 목록 양쪽에 추가한다. CSS 모듈의 로딩 순서도 확인한다.
4. `node scripts/check-site.cjs`를 실행한다. 정적 참조·JS 구문·테스트 실패가 있으면 고친다.
5. 아래 화면 점검을 수행한다. 결과·버전·제한을 일지에 기록한다.
6. 이전 공개 파일 묶음을 별도 백업하고, 사용자가 변경 파일 전체를 직접 게시한다. 이 문서의 명령은 Git·게시를 실행하지 않는다.
7. 실제 공개 주소에서 새로고침·백업 복원·기출 이미지·PWA 업데이트를 확인한다. 설치앱의 기존 창도 확인한다.

자동 검사 명령:

```powershell
node scripts/check-site.cjs
python -m http.server 8000 --bind 127.0.0.1
```

문서/단순 기능 검토는 `file:///C:/Users/jhpox/Kiyo/Project/hellokiyo-github/index.html#dashboard`도 가능하다. 설치·Service Worker는 localhost나 HTTPS에서 따로 검증한다. 설치 앱/다른 기기 기록이 자동 동기화될 것이라고 안내하지 않는다.

## 데이터와 콘텐츠 운영

문제 추가는 원본 확보 → 출처·연도·기준일·정답 검토 → 50문항/보기/그림 매핑 → ID·정답 범위 검사 → 화면 풀이 확인 순서다. `materials/papers/catalog.json`과 import 스크립트가 원본 추적의 기준이다. 개인 드롭 보관은 자동 문항 파싱이 아니다.

2026년 4회차는 공식 정답표 미확인 표기를 유지한다. 원본 미확보 3회차도 목록에서 상태를 숨기지 않는다. 자료 충족도 환산점을 실제 예상 점수·합격률로 홍보하지 않는다. 공식 답 변경 시 문제 ID·변경 이유·영향받는 기록을 남기고 정답과 해설을 함께 수정한다.

## 오류 접수와 처리 절차

현재 자동 제출되는 문의 서버는 없다. 운영자가 실제 수신 가능한 연락 수단을 정하기 전 ‘제보가 전송됨’ 같은 UI를 만들지 않는다. 사용자는 아래 정보를 운영자에게 선택한 채널로 전달하고 운영자는 기록을 분류한다.

필요한 정보는 버전·주소/경로·기기/브라우저·기능·문제 ID/회차/번호·재현 단계·기대/실제 결과·공식 근거·필요한 스크린샷이다. 개인 학습 JSON은 요청 목적과 제공 동의를 확인한 경우에만 전달한다.

접수→재현→분류(정답/저장/레이아웃/문의)→담당자 확인→수정→회귀검사→사용자 확인 순서로 처리한다. 접수됨/재현중/수정됨/추가정보필요 상태와 확인 날짜를 기록한다. 접수 창구·응답 담당자·목표 응답 시간은 운영자가 아직 정해야 할 사항이다.

## 장애와 복구

오래된 화면이면 설정의 최신 파일 갱신을 먼저 사용한다. 서비스 워커 캐시만으로 학습 데이터가 중앙 백업되지는 않는다. 기록을 살리려고 브라우저 사이트 데이터를 먼저 지우지 않는다. 파일 로컬 주소와 공개 주소 사이에서는 JSON 내보내기/가져오기로 이동한다.

새 버전 문제 발생 시 이전 정적 파일 묶음을 복원하고, 복원한 내용을 새 서비스 워커 버전으로 제공한다. 저장 스키마를 되돌리기 전에 호환 여부를 확인한다. v19처럼 새 필드가 늘어난 백업을 구버전 앱에서 가져오면 해당 필드를 무시할 수 있으므로 원본 JSON을 보관한다. 저장소 용량 부족·사생활 보호 모드·삭제된 브라우저 데이터는 서버 없이 자동 복구할 수 없다.

## 공개 전 남은 확인

공식 정답 대조, 실제 기기와 설치 앱 업데이트, 백업 파일 복원 실습, 운영 문의 채널 결정, 콘텐츠 이용 허용 범위 확인을 완료해야 한다. 실제 공개 호스트의 캐시 헤더·가용성·트래픽 한계는 이 로컬 검토에서 확인하지 않았다.

## 폴더 재배치 뒤 확인

현재 기능·설정은 [기능 목록](features.md)과 [설정 명세](settings.md), 루트와 하위 파일은 [파일 지도](file-map.md)에서 확인한다. 학습 원문은 `docs/study/exam-guide.md`, 테스트는 `tests/`다. 체커는 하위 JS·CSS 참조와 워커의 문서 목록까지 검사한다. 실행 주소와 저장 키를 바꾸지 않는 자산 폴더 이동은 학습 기록 이관을 요구하지 않는다. 폴더 재배치 이후에는 새 자산 경로를 모두 올려야 하며 index만 교체하지 않는다. 옛 URL의 캐시 갱신과 실제 설치 앱 확인은 별도 수행한다.
