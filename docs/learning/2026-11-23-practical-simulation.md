# 실험실을 실제 VM 없이 만드는 이유

## 상태를 흉내 내는 것과 OS를 실행하는 것

`domain/practical-lab.js`는 명령 문자열을 제한된 규칙으로 읽고 새 상태와 안내 문장을 반환한다. 실제 프로세스/라우터/네트워크는 없다. 따라서 사용자 입력에 eval/셸 명령을 사용하지 않고도 모드·IP·경로·저장을 연습할 수 있다. 실물의 링크·통신 실패와 모든명령은 재현하지 못하므로 UI에 지원범위를 명확히 표시해야 한다.

`pages/practical-lab-page.js`는 입력창·콘솔·케이블을 표현한다. 표시와 검사 규칙을 분리하면 DOM 없이도 모드이동·오입력·저장누락을 테스트할 수 있다. 실제VM/에뮬레이터가 필요한 경우에는 OS이미지라이선스,실행환경,지속저장,운영비용과보안을 별도검토해야 한다.

## 현재 설정과 저장 설정을 분리

running은 현재변경분이고startup은복사해둔구성이다. 두값을같은객체참조로두면현재설정변경이저장본까지바꿔저장누락을검사할수없다. 저장할때값을복사하고가상reload에서저장본을복원한다. 브라우저새로고침은임시실험실을초기화하지만따라하기완료는학습JSON으로별도보존한다.

연습: 저장→hostname변경→테스트에서저장조건미충족→가상reload→저장이름복원을확인한다. 이것이실제장비의모든부팅동작을재현한다는뜻은아니다.

## 날짜는 비밀키가 아니다

날짜코드요청은한국자정경계·다른시간대·탭절전복귀를고려해야한다. `platform/screen-lock.js`에서UTC+9로날짜를계산하고통과한날짜와비교한다. 자정/포커스복귀는가짜시계테스트로검사한다. 날짜는공개규칙이므로고정SHA비교구현을제거했다. 정적화면가림막과서버접근제어는계속구분한다.

## 창의 확인과 실제 적용을 분리

LabWindows의 draft는 편집 중 값, pending은 자식 창 확인을 거친 값, applied는 실제 가상 장비에 반영된 값이다. 부모 적용 전에 applied를 바꾸면 취소가 작동하지 않는다. 단일 창 폼은 단순 입력에 유리하지만, 이번에는 시험 조작 순서를 기억하려고 단계별 상태를 선택했다. 연습: IPv4 확인 후 부모 취소 → 기존 값 유지, 다시 입력 후 적용 → 테스트 결과 변경을 확인한다.

HTML Drag and Drop은 DataTransfer로 색과 출처를 전달한다. 도메인 placeWire에서 알려진 색·핀 범위와 원래 선의 일치를 검증해야 오래된 드래그가 다른 선을 덮지 않는다. 모바일에는 탭 대안을 유지한다. 포인터 이벤트 기반 터치 드래그는 추후 실제 기기 요구가 있을 때 검토할 수 있다.
