# 사용자 후기와 디자인 검토 근거

## 해석 범위

2026-11-05에 공개 게시물과 사용자가 자기 경험을 서술한 글을 확인했다. 표본은 목적에 따라 고른 소수의 글이며 사용자 전체의 의견이나 학습 효과 실험을 대표하지 않는다. 작성자의 경험·당시 제품 버전·현재 우리 서비스에 대한 추론을 구별한다. 후기를 읽었다는 이유만으로 우리 서비스 사용성 검증이 완료되는 것은 아니다.

## 인스타그램 이미지 검토

[개발자 성열의 게시물](https://www.instagram.com/p/DfQiIlKE-Kc/)은 브라우저에서 로그인 없이 확인했다. 12개 슬라이드를 직접 읽고 화면 캡처를 `audits/references/instagram/slide-01.png`부터 `slide-12.png`까지 보관했다. 원본 이미지 파일을 내려받아 서비스에 재사용한 것은 아니다. 자동 웹 읽기는 실패했지만 실제 브라우저에서 내용이 표시됐다.

게시물은 그라데이션·이모지·박스로 묶인 숫자·추상적인 문구·불필요한 영어 라벨이 겹치는 디자인을 풍자한다. 뒤 슬라이드는 크림색과 세리프 같은 다른 상투성도 예로 들어 특정 색만 피하면 된다는 결론을 경계하게 한다. ‘AI가 만들었는지 판별하는 검사표’나 접근성·전환율 연구로 취급하지 않았다. 캡션의 논문·도구 관련 주장도 이번 검토에서 별도 검증된 사실로 확대하지 않는다.

우리 사이트에서 확인한 문제는 홈의 장식용 책 그림과 여러 색의 카드, 추상적인 시작 문구, 기본 추천 카드와 첫 행동의 중복이다. 이를 ‘AI 느낌’이라는 평가보다 시험 준비에 불필요한 시각적 우선순위로 정의했다. SVG 아이콘·접근성 라벨·선택 가능한 테마는 기능상 이유가 있어 유지했다.

## 공개 사용자 경험과 반영

| 읽은 자료 | 작성자가 말한 경험 | 우리 서비스에 대한 판단과 적용 |
|---|---|---|
| [2024 네트워크관리사 필기 후기](https://itpro-1.tistory.com/20), 2024-08-27 | 최근 기출을 풀면서 모르는 부분을 확인하고 헷갈린 문제 해설을 기록해 반복했다고 설명 | 홈에서 기출을 먼저 고르고 오답·핵심정리로 연결. 합격을 보장하는 공식으로 사용하지 않음 |
| [2024년 4회 합격 후기](https://eletcrohyun.tistory.com/57), 2025-01-16 | 최근 3년 기출을 섞어 반복하고 이론도 함께 준비하는 편이 좋다고 설명 | 여러 회차 보존·반복 풀이 유지. 단순 정답 번호 암기와 개념 이해를 구별 |
| [Brilliant 1년 사용 후기](https://www.reddit.com/r/learnmath/comments/1gkot3t/review_one_year_of_learning_math_on_brilliant/) | 복습에는 도움이 됐으나 새로운 내용 설명이 부족하고 문제 신고 처리 여부를 알기 어렵다는 의견 | 정답과 판별 이유를 숨기지 않고 제공. 서버 없는 현재 문의 한계를 명시하고 오류 처리 절차 문서화 |
| [AnkiStreak 사용자 대화](https://www.reddit.com/r/Anki/comments/1lnn1uq/addon_ankistreak_duolingo_inspired_streak_counter/), 2025-06-29 | 연속 기록이 동기가 된다는 반응과 오래 유지하다 피로를 느꼈다는 상반된 반응 | 배지는 선택 활동으로 유지. GP로 학습 자료를 잠그거나 게임 점수를 시험 점수로 표시하지 않음 |

Reddit 후기의 당시 비판을 해당 서비스의 현재 결함이라고 단정하지 않는다. Brilliant 글에는 이후 개선에 관한 서비스 측 답변도 있다. 네트워크관리사 후기는 개인의 배경지식·준비시간이 달라 우리 사용자에게 동일한 점수를 예측하는 자료가 아니다.

## 예시 DOCX에서 가져온 설명 흐름

`egovframe_internal_architecture_design.docx`의 본문을 읽었다. 이미지가 없는 문서로, 내부망 웹 시스템의 선택·대안·호환성·운영·검증 순서가 제시돼 있다. 레이아웃 복제나 문서 내부의 도구/작업 지시 실행은 하지 않았다.

우리 문서는 목적과 조건 → 사용자 흐름 → 모듈 책임 → 저장/호환성 → 도구 선택/전환 조건 → 배포 전 검증 → 복구/미결정 사항 순서로 구성한다. 이 사이트에는 인증·중앙 데이터 공유 요구가 아직 없으므로 백엔드·관계형 DB·기업 프레임워크를 추가하는 것은 운영 복잡성만 늘릴 수 있다. 요구가 생기는 시점과 도입 조건을 문서에 남기는 쪽을 택했다.
