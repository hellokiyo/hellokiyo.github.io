## 오답 번호 복습·문제 이동 위치·6자리 화면 잠금 (v33)

### 질문 원문 (코드 가림)

> 오답 노트등에서 다음분제 넘어가면 번호로 넘어가는거 도입필요하고, /// 밑에 ui번호 넘어갈 필요없고 문제화면 그대로 있는게 좋아 그리고 고마고코드 입력하는 방식으로 지금 이페이지를 아무나 못들어오게 간단한 완전 간단한 비밀번호 만드는식으로 비밀번호는 날짜로 할까? 6자리 [입장 코드 가림]처럼

### 요약과 의도 해석

- 요약: 오답도 번호를 보며 이전/다음으로 풀고, 번호판으로 화면이 밀리지 않도록 한다. 날짜 형태6자리 코드로 간단하게 화면 진입을 가린다.
- 의도 해석(추정): 문제를 읽는 맥락을 유지하고 휴대폰 조작을 줄이면서, 아는 사람끼리 진입 코드를 공유하는 간단한 사용 흐름을 원한다.
- 확인한 기존 동작: 오답 재풀이에서 정답을 맞히면 전체 목록을 재렌더링해 펼친 위치가 사라졌다. QuizPage는 다음/번호 이동 후 스크롤·포커스 복구를 하지 않았다. 이번 관찰은 개발자의 코드/브라우저 확인이며 일반 사용자 후기 조사나 실제기기 테스트가 아니다.

### 선택 이유와 결과

- WrongNotebookPage에 출처+문항ID 쌍의 복습 목록을 시작 시 고정한다. 1/N, 이전/다음, 문제번호 입력과 이동, 목록 복귀를 제공한다. 정답이면 해당 출처 오답에서만 제외하되 현재 문제와 해설은 다음을 누르기 전까지 유지한다. 다른 기능에 남은 같은 문제는 지우지 않는다. 이 순차화 화면의 위치/답안은 메모리에서만 유지한다.
- PageUI.focusQuestion이 새 문제를 preventScroll로 먼저 포커스하고 문제 시작으로 스크롤한다. QuizPage의 다음/이전/번호와 오답 순차 이동에 연결한다. 번호판은 필요할 때 직접 쓸 수 있게 유지하며 다음 동작이 번호판으로 내려가지 않게 한다.
- 사용자 최신 명시 요청 범위에서 정적 화면 가림막(ScreenLock)을 추가했다. 기존 금지 지침을 서버 인증/회원가입 허용으로 넓히지 않았다. 날짜 형태 코드는 고정값이며 매일 자동 변경하지 않는다. 평문 코드를 코드/문서에 저장하지 않고 비교용 SHA-256만 둔다. 같은 탭의 sessionStorage에 통과 표시를 저장하고 설정에서 다시 잠글 수 있다. 학습기록/백업/개인 파일 저장소를 건드리지 않는다.
- WebCrypto가 없는 HTTP LAN에서도 작동하도록 숫자 코드의 ASCII SHA-256을 독립 모듈로 구현하고 Node crypto와 블록 경계값을 대조했다. 해시는 전송/파일 암호화/보안 인증을 뜻하지 않는다. 짧은 날짜 코드는 추측하기 쉬우며 공개JS를 분석할 수 있다.
- 시작 안내·잠금 화면·설정에 공개파일 접근제어가 아니라는 한계를 표시했다. 공개된 HTML/JS/HWP의 직접 접근을 막지 못하고 비밀번호를 아는 사람을 구별할 사용자 계정도 없다. 실제 접근차단이 필요하면 정적 호스팅 앞의 접근제어/별도 운영설계가 필요하며 이번에는 구축하지 않았다.

### 검증과 증거

- `node scripts/check-site.cjs`: 정적참조60개·전체JS구문·120테스트 통과. 새회귀는 출처별 완료 분리, 정답 후 위치 유지, 번호 경계값, 포커스 대상, SHA-256 경계 블록, 잘못된 통과 표시와 저장소 실패를 검사한다.
- localhost:4204 CCNA에서 실제 빠른 연습을 틀려 오답2개 생성 → 오답 순차 시작 → 정답 후1/2화면 유지 → 다음2/2 → 숫자1입력 이동을 확인했다. 일반 문제 다음 이동도 확인했다. 새 문제의 포커스는 question-box이며 화면 위쪽 약90px에 맞춰졌다.
- 데스크톱 기본 너비 및412x915 모바일 너비에서 확인. 해당 모바일의 viewport412px, 문서397px로 가로 넘침이 없었다. [오답 모바일 화면](../../audits/notebook-mobile-v33.jpg), [코드 화면](../../audits/screen-lock-mobile-v33.jpg).
- 잘못된 코드 거절, 요청 코드로 정상 해제, 설정의 다시잠금, 잠긴 상태 새로고침, 해제 후 같은탭 새로고침에서 통과유지 확인. 원문 코드 자체는 일지에 기록하지 않는다.
- 한계: 실제 아이폰/갤럭시 실기기·공개배포·오프라인 잠금·파일주소 실행은 미확인. 새 탭에서의 강제 재입력은 sessionStorage 설계 기준이며 브라우저 탭 복원/복제 정책에 따라 달라질 수 있다. 본 기능을 보안성 검증 완료로 표현하지 않는다.

### 승인·실행 흐름

- 이 서버는 검증용 정적 미리보기이며 앱의 인증서버/DB/운영백엔드가 아니다. 바인딩127.0.0.1, 포트4204. 방화벽·외부공개·Git명령·게시·계정·API키·외부 학습기록 전송 없음.
