### 요약과 의도 해석(추정)

정답 번호 안내를 넘어 문제별 대화로 개념을 자기 방식으로 이해하고 싶으며, 우선 본인만 사용해 품질·비용을 확인하고 싶은 요구다. 공개 페이지를 유지해도 개인 AI를 안전하게 쓸 수 있는지 우려한다.

### 선정 목적·이유와 결과

우선 실제 소스를 집계했다. 922문항 중 해설 필드 공백은 0개지만 800문항이 정답표/원문 안내에 그쳤다. 기능 검색 도우미는 생성형 AI가 아니므로 이를 AI라고 안내하지 않는다. 사전 생성 해설만 권하기보다 문제·내 답·추가 질문을 다루는 개인용 대화가 요구에 맞는다고 판단했다.

공개 정적 사이트 유지 + 서버에서 키 관리 + 본인 인증 후 AI 호출 구조를 제안했다. 로컬 서버만으로는 공개 주소/휴대폰 상시 사용을 충족하지 못하므로 선택지와 한계를 구분했다. UI 버튼 숨김이나 CORS만으로 인증을 대체하지 않는다. [설계·기술 학습](../learning/2026-11-14-ai-question-assistant.md)에 흐름·대안·검증 기준·공식 출처를 기록했다.

### 검증·한계

현재 문항 집계와 검색 도우미 소스, 기존 설정/구조를 읽었고 공식 GitHub/Cloudflare/OpenAI 자료를 확인했다. 제품 코드 변경, AI 서버/화면 구현, API 키 설정, 실제 모델 호출, 사용료 발생, 개인 인증, 배포는 수행하지 않았다. 실제 모델/예산/인증 방식은 아직 정하지 않았다. 앞선 구현 의향 설명을 구현 완료로 해석하지 않는다.

### 승인

사용자의 본인 전용 선택은 사용 범위에 대한 명시적 응답이다. 외부 계정 생성·결제·배포·보안 설정 변경 승인으로 확대 해석하지 않았다. 별도 권한 확대 요청은 없고 읽기·설계 문서 작성만 수행했다. Git 명령·GitHub 계정 접근·배포는 하지 않았다.

- 요약: 기존 전체 문항을 분석해 해설/검색 자료로 만들고 이후 소형 공개 모델과 결합하는 대안 평가.
- 의도 해석(추정): 실시간 유료 모델에 계속 의존하기보다 설명 품질을 축적하고 개인 로컬 AI로 확장하고 싶은 요구다.
- 선정 목적·이유: 지금도 쓸 수 있는 정적 해설과 미래의 모델 독립적인 지식베이스를 함께 준비하는 방안을 제안했다. RAG의 참고 자료 검색과 파인튜닝의 가중치 갱신을 구별했다. 현재 문항은 ID 직접 조회를 우선하고 개념별 검색이 필요해지면 인덱스를 추가하는 순서를 제시했다.

- 승인: 기존 허용 범위의 읽기·공식 자료 조사·문서 기록. 별도 권한 확대·유료 호출·배포·Git 작업 없음.

## 시험 서비스 독립과 AI 보조 방향 확인

- 질문 원문: “그럼 이 사이트는 다른 것들관 분리하고 대신 ai를 이용하는 방향으로 가는건가”
- 요약: 다른 프로젝트와 분리된 시험 서비스에 AI를 보조 수단으로 활용하는 방향인지 확인.
- 의도 해석(추정): 허브/호스팅 논의 뒤 최종 서비스 범위와 AI의 역할을 명확히 하고 싶은 요청.
- 선정 목적·이유: 기출·오답·오늘의 학습·산성비는 시험 학습 목적 아래 유지하고 개인 프로젝트/홈랩 관리와 UI를 혼합하지 않는 방향을 권했다. AI는 해설 이해와 추가 질문을 보조하며 핵심 학습 기능의 필수 의존성으로 두지 않는다.
- 결과: 공개 시험 사이트 유지, 검토된 정적 해설 개선, 기존 개인 로컬 AI의 선택적 활용을 현재 방향으로 정리했다. 무료·새 API 키/인증 토큰 관리 없음 제약을 유지하며 AI 미연결 상태에서도 기존 기능이 동작해야 함을 명시했다. 실제 직접 AI 연결은 미구현이다.
- 검증·한계: 방향 확인과 문서 기록만 수행. 사이트 경로 이동·허브 생성·AI 호출·모델 설치·제품 코드 변경 없음. 앞선 제안과 현재 구현 상태를 구별했다.
- 승인: 추가 권한·Git·배포·기존 기록/인증 변경 없음.
