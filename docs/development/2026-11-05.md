### 요약과 의도 해석

기능을 늘리는 것보다 어떤 조합이 시험 준비에 도움이 되는지 숫자로 비교하고, 제한된 공부 시간을 배분하려는 요청으로 해석했다. 이는 의도에 대한 추정이며 실제 사용자의 성적이나 이용 패턴을 뜻하지 않는다.

### 선정 목적과 선택 이유

2026년 기출 자체를 공부한 후 같은 문제를 평가하면 자료 효과를 과대평가한다. 따라서 2026년 전체를 학습 원천에서 제외하고, 정답 근거를 확인한 문항의 합집합으로 31개 조합을 집계했다. 기억률·소요 시간 자료가 없으므로 이를 예상 점수나 시간당 학습 효율이라고 부르지 않는다.

### 결과와 검증

`STUDY-PLAN-7-DAYS.md`와 `audits/2026-feature-*`에 저장했다. 산성비 평균 22점, 핵심정리 67.5점, 이전 기출 76점, 기출+핵심정리 88점 분량의 자료 근거를 확인했다. 전체 200문항, 31개 조합, 원천 ID, 중복·포함 관계를 검사했다. 단일 수동 판정이고 4회차 정답의 공식 대조가 미완료라는 한계가 있다.

### 돌아볼 점

기능 개수는 학습 범위와 같지 않다. 같은 콘텐츠를 다른 방식으로 반복하는 기능은 범위를 늘리지 않아도 회상 연습에 도움이 될 수 있다. 범위 평가와 실제 학습 효과를 따로 검증해야 한다.

## 2. 이용 패턴에 따른 다음 학습 추천

### 질문 원문

> 이런걸 사용자가 보기 쉽게 페이지 어딘가에 추가하는게 나을것같은데 산성비사용율이 너무 높으면 산성비도 좋지만 어떤기능을 사용해보는건 어떨까요 하면서 밑에 작은글씨로 이유 처럼 작성되어있고 이유에는 실제 계산 산성비는 실제 시험에서 큰 비중 차지않는 숫자근거를 제시한다던가 아니면 핵심정리 너무 많이보면 피도로 풀게 산성비로 유도한다던가

### 요약과 의도 해석

재미있는 기능에만 머무르거나 읽기만 반복하는 학습을 줄이고, 상황에 맞는 다음 행동을 안내하려는 요청으로 해석했다. 사용자를 통제하기보다 이유를 보여주고 스스로 선택하게 하는 것이 목적이라고 추정했다.

### 선정 목적과 선택 이유

- 홈과 학습 종료 화면에 작은 추천 카드를 두고 팝업을 피한다. 학습 흐름을 방해하지 않기 위해서다.
- 방문 횟수 대신 최근 7일 활성 이용 시간을 사용한다. 메뉴만 여러 번 누르는 행동을 공부 비율로 오인하지 않기 위해서다.
- 산성비에 치우치면 기출·핵심정리를 제안한다. 핵심정리를 연속 15분 이상 보면 짧은 산성비 전환을 선택지로 준다. 실제 피로도는 측정하지 않는다.
- 산성비 44/200(22%)는 검토 자료에서 충분한 답 근거를 확인한 비율이다. 실제 시험의 키워드 문제 비중·사용자 예상 성적이라고 표현하지 않는다.
- 운영 기준과 연구 결과를 구분한다. 60%·65%·15분 기준은 서비스의 초기 추천 규칙이며 실험으로 입증된 최적값이 아니다.
- 하루 동안 같은 추천을 숨길 수 있게 한다. 추천을 따른다는 강요를 줄인다.

### 결과와 검증

`assets/network/study-coach.js`와 CSS를 추가하고 홈·핵심정리 하단·산성비/문제풀이 종료 화면에 연결했다. 기본 홈 안내 외에는 해당 추천 조건을 충족할 때 표시한다. 게임 도중에는 노출하지 않고, 추천별 ‘오늘 숨기기’를 제공한다. 최근 7일 기록은 브라우저 로컬에만 보관하며 업데이트 후부터 쌓인다. 기존 기록으로 사용 시간을 추정하지 않았다.

현재 운영 규칙은 총 활성 시간 10분 이상이고 산성비 60% 이상(산성비 자체 5분 이상)이면 기출·정리를 제안한다. 기출 65% 이상이면 정리를 제안하고, 연속 활성 읽기 15분이면 산성비 전환을 제안한다. 창 숨김·포커스 이탈·게임 일시정지·2분 무조작은 제외한다. 최대 15초 단위의 근사 시간이고 여러 기기의 기록은 합산하지 않는다. 학습 기록 초기화 때 추천 기록도 초기화한다.

관련 신규 테스트 5개를 포함해 전체 72개 테스트가 통과했다. 짧은 게임 종료 시 시간 유실, 비활성·일시정지 시간 제외, 날짜별 보존, 추천 경계값, 감사 자료 숫자 일치를 확인했다. 실제 브라우저에서 홈 카드와 숫자 근거 펼치기를 확인했고, 모바일 너비에서 화면 375px·콘텐츠 375px로 가로 넘침이 없었다. 브라우저 오류 로그는 없었다. 모든 추천 조건을 실제 7일간 사용해 검증한 것은 아니며, 시간 조건은 자동 테스트로 확인했다. 스크린샷은 `audits/study-coach-mobile.png`다.

서비스 워커를 v14로 갱신하고 추천 리소스·7일 계획서를 오프라인 목록에 포함했다. 개발 기록은 앱 메뉴와 오프라인 학습 목록에 넣지 않았다. Git 연결·커밋·업로드는 하지 않았다.

### 다음에 검증할 가설

추천을 읽은 사람이 실제로 다른 학습으로 이동하는지, 이동 후 다시 오답을 맞히는지 확인해야 한다. 단순 클릭 증가만으로 학습 개선이라고 판단하지 않는다. 현재 기록은 해당 브라우저에만 저장하고 서버로 전송하지 않는다.

## 4. 왼쪽 아래 기능 검색 도우미

### 질문 원문

> 좌측하단이라던가 기능 검색 챗봇 같은걸 만들어볼까

### 요약과 의도 해석

메뉴 위치를 몰라도 말로 기능을 찾는 진입점을 원하는 것으로 해석했다. 앞선 ‘기출이 어디 있는지 사용자가 찾지 못함’ 문제를 완화하려는 목적이라고 추정했다. 사용자의 탐색 부담을 줄이는 방향으로 구현한다.

### 선정 목적과 선택 이유

왼쪽 아래 작은 버튼과 대화창을 닮은 검색 패널을 선택했다. 모바일에서는 하단 내비게이션 위에 놓는다. 질문 예시 3개와 직접 선택 메뉴를 함께 제공하여 사용자가 어떤 질문을 해야 할지 몰라도 이용할 수 있게 한다.

우선 규칙 기반 기능 검색과 기존 키워드·명령어 자료 검색으로 만든다. 일반적인 생성형 AI 챗봇으로 오인하지 않도록 화면에 이를 명시한다. API 비용·계정·외부 전송 없이 오프라인에서도 사용할 수 있고, 사이트에 없는 답을 만들어내지 않는 것이 선정 이유다. 문맥을 이해하는 범용 상담이나 문제 자동 풀이는 범위에 포함하지 않았다.

결과는 기능 설명과 바로가기다. 설정은 기존 설정 창을 열고, 용어 결과는 키워드/명령어 화면의 검색어에 연결한다. 산성비만 공부하는 질문에는 기존 수동 자료 검토 수치와 한계를 함께 보여준다. 입력은 브라우저 메모리에만 잠깐 표시하며 저장·외부 전송하지 않는다. 게임 플레이 중에는 버튼을 숨긴다.

### 결과와 검증

`assets/network/feature-helper.js`와 CSS를 추가했다. 질문의 다양한 표현, 계산 근거 안내, 명령어·용어 검색과 미일치 처리를 테스트했다. 기존 테스트를 포함한 75개가 통과했다. 서비스 워커를 v15로 갱신해 새 리소스를 오프라인 목록에 넣었다. 실제 브라우저에서 질문 예시→추천 결과→최신 기출 이동과 `ipconfig` 검색→명령어 노트의 해당 검색 결과 연결을 확인했다. 브라우저 오류 로그는 없었다. 모바일 390px 너비에서 패널이 하단 메뉴 위에 배치되는 모습을 확인했다. `audits/feature-helper-mobile.png`에 저장했다.

연도별 기출 찾기는 최신 기준 필터가 남아서 과거 회차를 가리는 일이 없도록 전체 연도·필터 해제로 연결했다. 시험·게임 도중 사용에 대한 모든 상호작용이나 실제 휴대폰 키보드 레이아웃은 완전 검증하지 않았다. Git 작업은 하지 않았다.

### 다음에 확인할 점

규칙 검색이므로 동의어를 충분히 등록하지 않으면 못 찾을 수 있다. 다른 사용자에게 실제로 자주 묻는 문장을 받아 검색 성공 여부를 확인하고 단어 목록을 보완한다. 검색창을 추가한 뒤에도 기출 메뉴 자체의 이름과 위치는 계속 찾기 쉬워야 한다.

### 요약과 의도 해석

매번 새로운 기능 탐색을 시작할 때 이전 검색어를 지우는 수고를 없애고 싶다는 요청으로 해석했다. 초기화를 반복할 때의 비용을 확인하고, 진입 버튼과 패널을 오른쪽 아래로 옮기려는 목적이다.

### 선정 목적과 선택 이유

검색 기록은 지속 대화가 아니므로 열기 이벤트에서 입력값·검색 결과·패널 스크롤만 초기화한다. 앱 전체나 자료를 다시 로드하지 않아도 된다. 이미 브라우저에 있는 데이터와 DOM만 사용하므로 이 초기화는 서버 요청을 만들지 않는다. 계속 실행하는 초기화 타이머도 추가하지 않는다.

오른쪽 아래에 버튼과 패널을 함께 정렬하고 모바일에서는 기존 하단 메뉴 위 여백을 유지한다.

### 결과와 검증

열 때마다 빈 입력·기본 안내 메뉴·스크롤 맨 위로 되돌아오도록 수정했다. 데스크톱과 모바일의 오른쪽 여백을 각각 22px·16px로 설정했다. 기존 검색·PWA 테스트 5개와 JavaScript 구문 검사를 통과했다. 별도 DOM 모형으로 질문 검색 후 다시 열었을 때 입력·결과·스크롤이 초기화되는지 확인했다. 이번 수정의 실제 브라우저 시각 재검증은 하지 않았다. 서비스 워커와 표시 버전을 v16으로 올렸다. Git 작업은 하지 않았다.

### 요약과 의도 해석

각 기능에서 틀렸던 내용을 별도 화면을 돌아다니지 않고 한곳에서 복습하려는 요청으로 해석했다. 문제의 원래 종류만 분류하는 것이 아니라 실제 학습한 기능을 출처로 남기는 것이 목적이라고 추정했다.

### 선정 목적과 선택 이유

오늘의 학습·산성비·키워드 암기·자체 문제풀이·기출문제로 출처를 분리한다. 원래 기출문제여도 오늘의 학습에서 틀리면 오늘의 학습 목록에 넣는다. 하나의 항목이 여러 기능에서 틀릴 수 있으므로 기능별 기록은 각각 보존하고 전체 개수만 항목 ID로 중복 제거한다.

기존 문제 오답은 출처 기록이 없어 ‘이전 기록’으로 보존한다. 과거 산성비는 개별 시도 기록을 장기 저장하지 않아 이전의 누락 오답을 복원했다고 주장하지 않는다. 키워드와 오늘의 학습의 모름·헷갈림은 복습이 필요한 기록으로 포함하고, 이를 안내 문구에 명시한다. 핵심정리·명령어 열람 자체는 오답 판정이 없으므로 임의의 오답 목록을 만들지 않는다.

오답 목록 안에서 바로 4지선다로 다시 확인하고, 맞히면 해당 기능의 목록에서만 제외한다. 키워드 항목은 원래 단서와 연결된 문제 예시로 복습한다. 정답·판별 근거는 펼쳐볼 수 있고, 수동 복습 완료도 가능하다. 기존 ‘오답 다시 풀기’의 문제풀이 방식은 호환성을 유지하며 그 방식에서 정답이면 해당 문제의 기능별 기록을 모두 완료한다.

### 결과와 검증

`wrong-notebook.js`에 출처별 저장·중복 제거·마이그레이션을 추가하고 저장/가져오기 정제 과정에 연결했다. 산성비는 오답·시간 초과·건너뜀 판정 즉시, 자체 연습은 답 확인 시, 실전은 제출 시 저장한다. 오늘의 학습은 기억 평가 시 저장한다. 기능별 필터와 목록 내 재풀이·제외하기를 제공한다. 전체 보기에서는 오답이 없는 기능의 빈 목록을 생략한다.

기존 기록 이관·알 수 없는 ID 제거·기능 간 중복·개별 완료·저장 왕복·게임 판정 콜백·키워드 헷갈림 전달을 검사했다. 기존 테스트를 포함한 전체 80개가 통과했다. 실제 브라우저에서 산성비 건너뜀 → 오답 개수 증가 → 산성비 목록 필터 → 문제 예시 재풀이 정답 → 해당 목록 제외를 확인했다. 모바일 화면을 `audits/wrong-notebook-mobile.png`에 저장했다. 브라우저 오류 로그는 없었다. 모든 출처의 전체 동선을 실제 기기에서 확인한 것은 아니며, 나머지 저장 경로는 코드·자동 테스트로 검증했다. 서비스 워커를 v17로 올렸다. Git 작업은 하지 않았다.


## 7. 누적 배지를 한 판 최고 기록 도전으로 변경

### 질문 원문

> 배지 컬렉션도 좀 바꿔야할것같애 누적이면 너무 쉬워 점수를 올린다던가 1회 최대최고점수로 한다던가

### 요약과 의도 해석

반복 횟수만 늘리면 쉽게 얻는 보상 대신 한 번의 도전에서 더 높은 성취를 요구하는 배지를 원하는 것으로 해석했다. 단순 활동량보다 개인 기록 갱신을 동기로 삼으려는 목적이라고 추정했다.

### 선정 목적과 선택 이유

누적 기준을 없애고 5문항 이상 플레이한 한 판 최고 점수를 사용한다. 입력 부담이 다른 4지선다와 직접 입력의 배지는 별도로 둔다. 목표는 1,000 / 2,500 / 5,000 / 8,000 GP로 정했다. 현재 콤보 점수식에서 연속 정답 8개가 1,080 GP여서 첫 배지도 한 판의 연속 회상이 필요하다. 난도는 실제 사용자 성적 분포로 최적화한 값이 아닌 초기 운영 목표다. 기존 최고 점수는 인정하고 누적 GP는 활동 기록으로만 보존한다.

### 결과와 검증

모드별 최고 기록, 달성 배지, 다음 목표까지 필요한 점수를 표시한다. 낮은 점수 여러 판의 누적으로는 배지가 열리지 않는다. 같은 목표 재달성으로 획득 알림이 반복되지 않는다. 모바일은 배지를 2열로 배치한다. 관련 게임·PWA 테스트 13개가 통과했다. 누적 점수 무관성, 8연속 정답 목표 달성, 모드별 분리, 기존 기록 보존, 재획득 방지를 검사했다. 이번 변경의 실제 브라우저 시각 검증은 하지 않았다. 서비스 워커 버전은 v18이다. Git 작업은 하지 않았다.
